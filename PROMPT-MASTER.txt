4. DIREÇÃO VISUAL OBRIGATÓRIA
======================================================================

A interface deve comunicar profissionalismo, credibilidade, tecnologia, clareza, organização, sofisticação, inovação e elegância.

O conteúdo é o protagonista. Priorize hierarquia visual, legibilidade, contraste, alinhamento, espaços de respiro e consistência.

Evite expressamente:
- estética gamer, cyberpunk, Matrix ou terminal;
- scanlines, cursor piscando e brilho neon;
- gradientes chamativos e decoração excessiva;
- partículas ou animações contínuas sem função;
- sombras e halos exagerados;
- cartões em excesso;
- loaders artificiais ou animações que atrasem o conteúdo.

Não copie cegamente o layout de outro projeto. Cada produto mantém personalidade própria dentro do sistema institucional.

6. SISTEMA CSS E COMPONENTES
======================================================================

Implemente tokens CSS semânticos como fonte única de verdade. Componentes devem consumir variáveis, nunca espalhar valores de cores avulsos.

Padronize:
- tipografia Inter ou Manrope; IBM Plex Mono para detalhes técnicos;
- escalas fluidas com clamp();
- container, grids, espaçamentos e breakpoints;
- cabeçalho e navegação desktop/mobile;
- botões primários, secundários, ghost e destrutivos;
- cartões, formulários, campos e mensagens de validação;
- modais, dropdowns, abas, tabelas, alertas e feedbacks;
- estados hover, focus-visible, active, disabled, error e success;
- imagens, SVGs, ícones e seus comportamentos em ambos os temas.

Utilize CSS Grid e Flexbox. Adote mobile-first, `minmax()`, `clamp()`, `rem` e largura adaptável. Não crie estrutura de arquivos excessivamente fragmentada sem benefício. Respeite a arquitetura do framework, caso exista.

7. SISTEMA DAY & NIGHT — INTEGRAÇÃO DO COMPONENTE ORIGINAL
======================================================================

Utilize o componente original do repositório DAY & NIGHT EXPERIENCE:
https://github.com/eliseuangelos/day-night-experience

**REGRA OBRIGATÓRIA: importar o componente diretamente por URL externa. Não baixar, copiar, duplicar, editar ou hospedar localmente `component/day-night.js` nem `component/day-night.css`.** Não criar pastas `vendor/day-night`, `lib/day-night` ou equivalentes para esses arquivos.

O manual oficial disponibiliza estas duas opções:

**Opção recomendada para produção — jsDelivr com versão fixa `v1.3.0`:**

CSS:
https://cdn.jsdelivr.net/gh/eliseuangelos/day-night-experience@v1.3.0/component/day-night.css

JavaScript:
https://cdn.jsdelivr.net/gh/eliseuangelos/day-night-experience@v1.3.0/component/day-night.js

**Alternativa — GitHub Pages:**

CSS:
https://eliseuangelos.github.io/day-night-experience/component/day-night.css

JavaScript:
https://eliseuangelos.github.io/day-night-experience/component/day-night.js

Escolha somente uma origem por projeto. Para produção, prefira a versão fixa do jsDelivr indicada pelo manual. Antes de atualizar a versão, consulte novamente a documentação oficial e confirme a tag/release. Não invente endereços ou versões.

Exemplo de integração básica com jsDelivr:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/eliseuangelos/day-night-experience@v1.3.0/component/day-night.css">
<script src="https://cdn.jsdelivr.net/gh/eliseuangelos/day-night-experience@v1.3.0/component/day-night.js"></script>
<script>
  if (typeof DayNight !== 'undefined' && typeof DayNight.init === 'function') {
    DayNight.init({ position: 'top-right' });
  }
</script>
```

A chamada `DayNight.init({ position: 'top-right' })` corresponde à integração básica apresentada na demonstração e no manual do próprio projeto. Não presumir nomes de parâmetros ou opções adicionais. Para personalizações, consultar a documentação vigente e o código de integração gerado pelo construtor oficial; só utilizar configurações confirmadas.

Não implemente um alternador concorrente. Não mantenha dois sistemas de persistência ou duas fontes de verdade para o tema.

Padrão de tema documentado:
- DIA: `data-theme="light"`
- NOITE: `data-theme="dark"`
- Preferência persistida: `dn-theme`

O projeto pode manter um pequeno script próprio de inicialização anti-flash, no `<head>`, para aplicar o valor de `dn-theme` ou, quando ainda não houver escolha salva, respeitar `prefers-color-scheme`. Esse auxiliar não deve implementar outro controle de alternância nem outra chave de armazenamento. O componente remoto permanece responsável pela interação e persistência.

Carregue os dois temas CSS próprios da aplicação simultaneamente sempre que possível. O CSS estrutural deve utilizar apenas tokens semânticos. Não utilize `filter: invert()`.

Atualize `meta name="theme-color"` de acordo com o tema ativo, quando tecnicamente possível e compatível com os navegadores alvo. Se houver CSP, autorize o domínio da origem externa escolhida em `style-src` e `script-src`.

9. PROCEDIMENTO DE TRABALHO
======================================================================

Antes de alterar código:

1. Inspecione a estrutura completa do projeto.
2. Identifique framework, build, hospedagem, rotas e base path.
3. Leia HTML, CSS e JavaScript existentes.
4. Identifique funcionalidades, integrações e componentes que devem ser preservados.
5. Verifique os caminhos atuais de ícones, imagens, fontes e scripts.
6. Analise se já existe tema, alternador ou persistência para evitar duplicidade.
7. Consulte a documentação e a API atual do DAY & NIGHT EXPERIENCE.
8. Defina um plano mínimo de mudanças, mantendo a arquitetura válida.

Durante a implementação:

- preserve conteúdo, lógica de negócio e funcionalidades existentes;
- não reconstrua a aplicação do zero quando uma evolução for suficiente;
- não modifique dados ou textos sem necessidade;
- não remova componentes funcionais para substituí-los por decoração;
- evite dependências adicionais quando HTML, CSS e JavaScript nativos forem suficientes;
- adapte cada componente à finalidade real da aplicação;
- mantenha os dois temas completos;
- integre os créditos sem comprometer o layout;
- não faça adaptações locais nos arquivos remotos DAY & NIGHT; ajuste a aplicação ao componente e documente configurações adicionais confirmadas.
